把“怎么干活”打包，

一句话：Skill（技能包）＝一个装着 SKILL.md（指令） 的文件夹，把做某类事的步骤、知识、甚至脚本打包成可复用单元；Agent 遇到相关任务才按描述加载它——像给新员工的入职手册。

02

解剖：一个 Skill 长什么样

Skill = 一个目录；最简只需 SKILL.md（本仓库的 concept-microcourse 同款结构）

my-skill/
├── SKILL.md          # 必填：YAML 头 + 指令正文
├── references/       # 可选：按需读取的参考文档（如设计规范）
├── scripts/          # 可选：可执行代码
├── assets/           # 可选：模板等资源
01
🏷️ YAML 头 · 最少两行
name（唯一名）与 description（干什么、何时用）。Agent 靠它判断“要不要加载我”。
02
📋 指令正文 · Markdown
一步步教 Agent 怎么干：流程、规范、检查清单。Anthropic 建议单个正文尽量控制在 5k token 内，超长拆到引用文件。
03
📦 周边资源 · 按需引用
同一目录下的 references / scripts / assets，被正文点名才读取；脚本不进上下文、直接执行，保证结果确定。

放在仓库的项目级 Skill（如本仓库 .workbuddy/skills/concept-microcourse/）就是同一套规则：SKILL.md 开头写 name 与 description，正文是可复用的工作流程。

03

核心机制：渐进式披露

Progressive Disclosure
🏷️ 第 1 级 · 发现：只把每个 skill 的 name / description 放进上下文
↓ 任务来了，Agent 判断“与描述匹配”
2
📋 激活：读取 SKILL.md 全文
完整指令此刻才进入上下文，开始按步骤干活。
↓ 步骤需要时才打开
3
📦 执行：按需加载脚本 / 参考 / 模板
只在特定子任务命中时读取；代码则直接执行，不进上下文。
↺ 平时只占一点点开销；装几十个技能也不怕把上下文撑爆

这正是 Anthropic 强调的“模型在上下文聚焦、信息相关时表现更好”——与“上下文”那页讲的注意力预算是同一件事。

招人时不可能把公司所有规范记在招聘广告里（会爆上下文）。入职手册随取随用：要做报销时翻报销章、要做 PPT 时翻模板章。

🥋 “加载”功夫的功夫片

Anthropic 内部调侃过：Skill 就像《黑客帝国》里 Neo 一键加载格斗技能——平时不带，需要时“嗞”地进入脑子。

05

一个具体场景

本仓库：concept-microcourse 学习页生成器
1️⃣

用户开口：“学一下大模型的上下文，做一页能自测的 HTML”。

2️⃣

自动匹配：Agent 扫描 .workbuddy/skills/，发现 concept-microcourse 的 description 命中“概念速学 HTML”。

3️⃣

只读正文：把 SKILL.md 全文读入上下文，按里面 7 步流程组织内容——不靠每次口头重讲。

4️⃣

按需开文件：要排版时读 references/design-tokens.md，要出题时读 references/quiz-engine.md。

5️⃣

稳定产出：同样的风格、同样的自测引擎，换成任何一个新概念都能复用——这就是“沉淀可复用任务知识”。

同样的事若没有 Skill：每次都把设计规范、测验 JS、排版规则再解释一遍——浪费上下文、且结果漂移。有了 Skill，方法与产出一次比一次一致。

06

别混淆

边界在哪
🛠️ Skill vs MCP 工具Tool
工具回答“能做什么”（读库、发邮件），Skill 回答“怎么做才好”（流程、规范）。两者不同层、常互补：Skill 正文里可以指导 Agent 去调工具。
💬 Skill vs 系统提示词System Prompt
提示词每会话都得带、长期占上下文；Skill 平时只留 name＋description，命中才加载全文——解决“每会话重讲一遍”的痛点。
🔎 Skill vs RAG 资料库Retrieval
RAG 检索的是“片段事实”；Skill 更偏程序性知识（怎么做 + 可执行代码）。资料文件可以被 Skill 引用，不是一回事。
🤖 Skill vs Agent
Skill 是零件（能力包），Agent 是组织者——它自主决定何时加载哪个 Skill、如何组合使用。
🎯 触发机制
Skill 不需要用户点名，靠 description 被 Agent 自动匹配。description 写得好不好，直接决定“该用时会不会被叫醒”。
🧨 安全雷区
恶意 Skill 里的指令/脚本可能诱导越权或外泄数据。官方建议：只从可信来源安装，对陌生来源要审计其捆绑代码与网络指令。
  • 一句话边界：凡是有“稳定的做事方法”且“每次都要重新解释”的活儿，就值得打包成 Skill；不稳定的一次性对话，直接写提示词更省事。

1. 先读全文，提取关键论据。
2. 输出 3 条要点，每条 ≤ 一行。
08

五行速记

01

Skill = 含 SKILL.md 的文件夹：YAML 头写 name/description，正文写“怎么做”。

02

本质是程序性知识包：把专家的“做法”沉淀成可复用单元。

03

平时只暴露一行简介，命中才加载全文——省上下文、还稳。

04

和工具互补：工具给“能力”，Skill 给“用法”；Agent 当组织者。

05

安全第一：只装可信来源，陌生 Skill 先审计脚本再放行。
